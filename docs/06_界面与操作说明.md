# 06_界面与操作说明

负责人：6 号　版本：v0.3（2026-11-26，第二阶段联调）
读者：任课教师、组内成员、演示讲解人。

本文件说明系统的启动方式、界面布局、五个区块中**每一个控件的作用与操作结果**、字段口径和常见错误。页面只做展示，不计算投档规则；数据来自 `src/api/main.py` 的 11 个既有端点和第二阶段新增的统计导出端点（待 1 号登记契约）。

## 1 启动与访问

### 1.1 环境

- Python 3.11 及以上；依赖 `fastapi`、`uvicorn`（安装见 `deploy/README.md`）。
- 浏览器：Chrome / Edge 最新版。

### 1.2 mock 模式（无数据库，完整页面演示）

```powershell
# Windows PowerShell
$env:API_MOCK="1"; python -m uvicorn src.api.main:app --reload --port 8000
```

```bash
# Git Bash / macOS / Linux
API_MOCK=1 python -m uvicorn src.api.main:app --reload --port 8000
```

浏览器打开 `http://127.0.0.1:8000`。mock 数据在 `src/api/mocks.py`，字段与 4 号 `docs/04` 对齐。

| 类型 | mock 可用编号 | 说明 |
| --- | --- | --- |
| 运行 | `RUN20261121-01` / `RUN20261121-02` | 调整前 / 调整后，案例对比页固定用这两个 |
| 考生 | S01—S06 | S01 甲、S02 乙、S03 丙、S04 丁、S05 戊、S06 己 |
| 计划 | P-A3、P-B3、P-G3、P-C2、P-D1、P-E4、P-LARGE | P-G3 无人录取；P-LARGE 120 条用于分页 |
| 学校 | H01、H02、H03 | A 校、B 校、C 校 |

### 1.3 真实模式（2/3/4 号模块就绪后）

```bash
python -m uvicorn src.api.main:app --reload --port 8000
```

- 数据库默认 `data/app.db`；可用 `SIM_DB` 或 `ZKS_DB` 指定其他路径（两者指向同一个库）。
- 数据库不存在时，“新建运行”会建库（主表 + run + 结果/日志表）；已存在但缺表时返回 503，不自动删库。
- 真实模式不会回退假数据：库未就绪返回 503，模块未就绪返回 501，页面提示条显示具体原因。
- 当前 `/execute` 仍依赖 2 号 `load_dataset`/`write_results`，未就绪时返回 `501 依赖未就绪: src.store.write_results`；完整投档等 2/3 号补齐后再联调。

### 1.4 访问方式

必须通过 `http://127.0.0.1:8000` 访问，不要直接双击 `interface/index.html` 用 `file://` 打开——页面能显示，但 `js/api.js` 请求不到后端。

### 2.3 推荐操作顺序

1. 运行控制：新建运行 → 完整运行（或按批执行）→ 看进度与余额。
2. 考生查询：查某考生的去向与每个志愿的处理原因。
3. 计划与名单：查某计划的名单、余额、最低分、末位考生、转入名额。
4. 统计：查批次统计、批次计划明细、分数分布、学校总体/分批/分类/计划统计，导出 CSV。
5. 案例对比：同一考生调整志愿前后两次运行的左右对照。

## 3 区块 01：运行控制

### 3.1 用途

创建一次模拟运行、选择数据规模、执行全部或指定批次、查看运行进度和各批计划余额。

### 3.2 控件逐一说明

| 控件 | 位置 | 作用 | 操作与结果 | 调用端点 |
| --- | --- | --- | --- | --- |
| 数据规模 | 运行参数面板左侧 | 选择本次运行使用小数据集还是 15 万规模数据 | 下拉“小数据集 / 15 万”；只在下一次点“新建运行”时生效 | `POST /api/runs` 的 `scale` |
| 批次 | 运行参数面板 | 选择“执行所选批次”要执行的批次 | 下拉 1—4：自主招生、名额分配、第三批统招、第四批统招 | `POST /api/runs/{run_id}/execute` 的 `batches` |
| 新建运行 | 运行参数面板右侧 | 创建运行编号，作为后续查询、执行、导出的依据 | 成功：顶部状态变为“运行 RUN…”，提示“已创建运行…”，`run_id` 写入 `localStorage`；真实模式首次会建库。失败：400/501/503 | `POST /api/runs` |
| 完整运行（1—4 批） | 运行参数面板右侧（蓝色） | 按第一至第四批顺序执行完整投档 | 成功：进度 100%，提示“运行 RUN… 已完成”，余额表刷新。未新建运行：提示先新建 | `POST /api/runs/{run_id}/execute`，`batches=[1,2,3,4]` |
| 执行所选批次 | 运行参数面板右侧 | 只执行“批次”下拉选中的那一批 | 成功：进度显示该批完成，余额表显示该批余额。未新建运行：提示先新建 | `POST /api/runs/{run_id}/execute`，`batches=[选中批次]` |
| 运行进度条 | 运行进度面板 | 直观显示完成比例 | “已完成”100%；“执行中”按 `done/total` 计算；失败停在当前值 | `GET /api/runs/{run_id}/progress` |
| 进度文字 | 进度条下方 | 显示阶段、完成数/总数、百分比、失败详情 | 初始“阶段：未开始　进度：0/0（0%）”；完成后“阶段：已完成　进度：4/4（100%）” | 同上 |
| 运行提示 | 运行参数面板底部 | 显示当前运行状态 | 初始“尚未创建运行”；刷新恢复“当前运行 RUN…”；新建“已创建运行…”；执行中“正在执行批次…”；完成“运行 RUN… 已完成”；失败“运行 RUN… 失败：详情” | 前端状态 + 执行/进度端点 |
| 各批余额表 | 运行进度面板下方 | 展示每批计划数、已录人数、剩余名额 | 列“批次 / 计划数 / 已录 / 余额”；无数据显示“无数据”；空值显示“无”。mock 有四批样例；真实模式 `/execute` 成功后由 4 号批次统计组装 | `GET /api/runs/{run_id}/progress` 的 `balances` |

### 3.3 操作步骤

1. 选“数据规模”（默认小数据集）。
2. 点“新建运行”，确认顶部出现 `运行 RUN…`。
3. 点“完整运行（1—4 批）”；或先选“批次”，再点“执行所选批次”。
4. 观察进度条、进度文字和余额表；完成后再去 02—05 查询。

### 3.4 边界与错误

- 没新建运行就点执行：提示“请先在‘运行控制’新建运行”。
- 刷新页面：`run_id` 从 `localStorage` 恢复，顶部与运行提示显示当前运行；余额/分布显示“无数据”，重新执行或查询后才有内容。
- mock 重复点“新建运行”：始终返回 `RUN20261121-01`。
- 真实模式：`run_id` 由 `run_meta.create_run` 递增；首次建库会补齐 `schema_run.sql`、`schema_log.sql`。
- 真实模式依赖未就绪：如 `501 依赖未就绪: src.store.write_results`；不会静默返回假数据。
- 执行中重复点击：按钮禁用，不会重复提交。
- 进度轮询：每 800ms 调一次进度，`done`/`error` 时停止。

### 4.1 用途

输入考生编号，查看其录取去向、每个志愿的处理状态和未录取原因。

| 控件 | 位置 | 作用 | 操作与结果 | 调用端点 |
| --- | --- | --- | --- | --- |
| 考生编号输入框 | 查询面板 | 输入要查询的考生编号 | 占位“如 S01”；Enter 等同“查询” | — |
| 查询按钮 | 输入框右侧（蓝色） | 查询该考生在当前运行下的结果 | 成功：出现结果卡；404 提示“考生不存在或该运行无结果”；未新建运行提示先新建 | `GET /api/students/{sid}/result?run_id=` |
| 结果卡 | 查询面板下方 | 显示考生信息与录取结论 | 字段：考生、姓名、初中、总分、同分序号、是否录取、录取批次、录取计划、学校、志愿序号、录取顺序；未录取时批次/计划/学校/志愿序号/录取顺序显示“无” | 同上 |

### 4.3 操作步骤

1. 确认顶部已有 `运行 RUN…`；没有则先到 01 新建运行。
2. 输入考生编号（mock 可用 S01—S06）。
3. 点“查询”或按 Enter。
4. 看“是否录取”和各志愿的“录取/跳过/未判定 + 原因”。

### 4.4 边界与错误

- 未新建运行：提示先新建。
- 考生不存在：`404 考生不存在或该运行无结果`。
- 未录取考生：录取字段全部“无”，原因写在对应志愿行。
- 状态 `pending` 表示该志愿没有判定记录（未跑到/数据缺失），页面显示“未判定”。

输入计划编号，查看计划的名额、转入名额、有效计划数、余额、最低/最高录取分、末位考生和名单，并分页浏览。

| 查询按钮 | 查询面板右侧（蓝色） | 查询该计划 | 成功：出现汇总卡和名单表；404 提示“计划不存在” | `GET /api/plans/{pid}/admissions?run_id=&page=&size=` |
| 汇总卡 | 查询面板下方 | 显示计划级统计与口径 | 字段：计划、学校、批次、类别、控制线、名额、转入名额、有效计划数、已录、余额、最低录取分、最高录取分、末位考生、完成情况 | 同上 |

### 5.3 操作步骤

1. 确认已有运行编号。
2. 输入计划编号（mock 可用 P-A3、P-G3、P-LARGE）。
3. 点“查询”或按 Enter。
4. 看汇总卡口径，再用上一页/下一页；P-LARGE 120 条可验证三页分页。

### 5.4 口径与边界

- 最低录取分＝已录考生总分最小值；末位考生＝实际录取顺序最后录取者，两者分别计算，可能不是同一人。
- 无人录取：最低分、最高分、末位考生都显示“无”，不得显示 0。
- 未完成计划：余额大于 0 时“完成情况”显示“未完成”。
- 有效计划数＝初始名额 + 转入名额（`carry_in`）；当前 mock 的 `carry_in` 为 0，真实库从 `carry_log` 汇总。
- 计划不存在：`404 计划不存在`。
- 每页最多 500 条（后端校验），页面只提供 20/50/100。

### 6.4 口径与边界

- 完成率＝已录人数 / 有效计划数；后端同时返回 `completion_rate`（0—1）和 `completion_rate_text`，页面优先显示文本。
- 完成率 0 显示“0.00%”，不显示“无”；无人录取的最低/最高分显示“无”。
- 批次 4 的 mock 示例：有效计划 2、录取 0、完成率 0.00%、最低/最高分“无”。
- 统计与明细分开：批次统计、批次计划明细、分数分布、学校总体/分批/分类/计划是不同表，不混算。
- 统计 CSV 是第二阶段新增端点，需 1 号在 `docs/00_契约.md` 第 6 节登记后才能算正式契约；未登记前按“6 号接口扩展”对待。

## 7 区块 05：案例对比

### 7.1 用途

对同一考生，比较“调整志愿前”和“调整志愿后”两次运行的结果，观察录取去向、志愿状态和原因码变化。

### 7.2 控件逐一说明

| 控件 | 位置 | 作用 | 操作与结果 | 调用端点 |
| --- | --- | --- | --- | --- |
| 考生编号 | 对比面板 | 要对比的考生 | 默认 `S01`；Enter 等同“对比” | — |
| 调整前 run_id | 对比面板 | 第一次运行的编号 | 默认 `RUN20261121-01`（mock） | — |
| 调整后 run_id | 对比面板 | 第二次运行的编号 | 默认 `RUN20261121-02`（mock） | — |
| 对比按钮 | 对比面板右侧（蓝色） | 同时查两次运行下该考生的结果 | 成功：左右两栏出现；任一运行查不到该考生：404 提示 | `GET /api/students/{sid}/result?run_id=`（调用两次） |
| 左/右栏 | 面板下方左右 | 显示两次运行的结果 | 字段：考生、姓名、初中、总分、是否录取、录取批次、录取计划、志愿序号；下方逐志愿显示状态与原因 | 两次调用 |
| 差异高亮 | 两栏志愿列表 | 标出计划/状态/原因变化的志愿 | 变化行浅黄底、左侧橙色竖线；未变化无底色 | 前端对比 |

### 7.3 操作步骤

1. 确认两次运行都已存在（mock 默认即可）。
2. 输入考生编号与两个 run_id。
3. 点“对比”。
4. 先看两栏“是否录取/录取计划”，再逐志愿看状态与原因变化；黄色行是差异。

### 7.4 边界与错误

- mock 固定 `RUN20261121-01` / `RUN20261121-02`；S01 调整前录取 P-A3，调整后未录取（P-B3 与 P-A3 均 R02），用于演示。
- 真实模式由 5 号提供两套数据与两次运行 `run_id`；页面不创建这两次运行。
- 任一 run_id 不存在或该考生无结果：404 提示。

## 8 字段与显示规则

### 8.1 字段来源

| 界面标签 | 接口字段 | 来源/口径 |
| --- | --- | --- |
| 考生/姓名/初中 | `student_id` / `name` / `junior_school` | `student` + `middle_school` |
| 总分 | `score` | 中考总分，整数 |
| 同分序号 | `tie_seq` | 越小越优先 |
| 是否录取 | `admitted` | 结果表是否有该考生记录 |
| 录取批次/计划/学校 | `batch` / `plan_id` / `school` | `admit_result` + `plan` + `high_school` |
| 志愿序号/录取顺序 | `volunteer_no` / `admit_order` | 被录志愿与计划内顺序 |
| 名额/转入/有效计划 | `quota` / `carry_in` / `quota_total` | `plan.quota` + `carry_log` 汇总 |
| 已录/余额 | `admitted_count` / `remaining` | 结果计数 / `plan.remaining` |
| 最低/最高录取分 | `min_score` / `max_score` | 已录考生总分最小/最大值 |
| 末位考生 | `last_admitted` | `admit_order` 最大者，含总分、志愿、同分序号 |
| 计划数/录取数 | `plan_count` / `admitted_count` | 统计口径 |
| 完成率 | `completion_rate` / `completion_rate_text` | 已录 / 有效计划数 |
| 未完成名额/剩余名额 | `unfilled_quota` / `remaining_quota` | 有效计划−已录 / 余额汇总 |
| 未完成计划数 | `unfilled_plans` | 余额 > 0 的计划条数 |
| 填报人数/未录人数 | `volunteered_students` / `unadmitted_students` | 该批填报去重人数 / 填报但本批未录人数 |
| 分数分布 | `buckets[].low/high/label/count` | 已录考生分数段 |
| 参考线 | `lines.control_line/gradient_first/gradient_delta` | `config/rules.toml` |
| 原因码/文案 | `reason_code` / `reason_text` | R01—R07，见 8.2 |
| 存在标记 | `exists` | 对象不存在时 6 号网关转 404 |

### 8.2 原因码

| 码 | 页面文案 | 适用批次 |
| --- | --- | --- |
| R01 | 未达计划控制线或最低控制线 | 全部 |
| R02 | 计划名额已满 | 全部 |
| R03 | 不在自主招生资格名单或排名不达 | 第一批 |
| R04 | 前批已录取 | 第二至第四批 |
| R05 | 非所属初中名额 | 第二批 |
| R06 | 志愿或计划无效 | 全部 |
| R07 | 未填报该计划 | 全部 |

原因码由 4 号 `all_reasons()` 提供；页面优先用返回的 `reason_text`，无则用 `renderReason(code)` 映射。

### 8.3 空值与状态

- 分数、余额、批次、计划、学校、志愿序号、录取顺序、最低/最高分、末位考生为 `null` 时一律显示“无”，不得写 0（R32）。
- `0` 是有效值：录取数 0 显示“0”，完成率 0 显示“0.00%”。
- 志愿状态：`admitted`→“录取”，`skipped`→“跳过”，`pending`→“未判定”。
- 未完成计划：余额大于 0 时“完成情况”显示“未完成”。
- 空值与“无”只在 `interface/js/render.js` 处理，页面脚本不自行判断。

### 8.4 分页

- 计划名单每页 20 / 50 / 100 条，默认 50；翻页只请求当前页。
- 15 万规模数据下禁止一次渲染全部行；`page` 从 1 开始，`size` 上限 500，默认 100。
- 第 1 页禁用“上一页”，最后一页禁用“下一页”。

## 9 常见错误与处理

| 页面现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `503 数据库未就绪` | 真实模式没有 `data/app.db`，或库里缺 student/plan/admit_result/admit_log/volunteer | 先“新建运行”建库；或按 `deploy/README` 建库并装载数据 |
| `501 依赖未就绪: src.store.write_results` | 2 号 `write_results` 还没实现/合入 | 用 `API_MOCK=1` 演示；等 2 号 W2 合入 |
| `501 依赖未就绪: src.gen_data` | 2 号 `load_dataset` 还没实现/合入 | 同上 |
| `404 考生不存在` / `404 计划不存在` / `404 学校不存在` | 编号拼错，或该运行下没有这个对象 | 核对编号；mock 可用 S01—S06、P-A3/P-G3/P-LARGE、H01—H03 |
| `404 运行不存在` | `run_id` 不属于当前数据库 | 重新“新建运行” |
| `422` | 缺少 `run_id` 等必填参数 | 正常页面操作不会出现；检查是否直接调端点 |
| 结果一直“无数据” | 还没执行投档，或运行编号不对 | 回 01 执行完整运行/对应批次 |
| 页面空白/按钮无反应 | 用 `file://` 打开，或服务没启动 | 用 `http://127.0.0.1:8000` 访问 |
| 导出没有反应 | 浏览器拦截下载，或未新建运行 | 允许本站下载；先新建运行 |
| 刷新后提示先新建运行 | 浏览器清除了 `localStorage` | 重新“新建运行” |
| 真实模式余额表为空 | `/execute` 尚未完成或 `balances` 未生成 | mock 有样例；真实模式需 2/3 号补齐后重跑 |

## 10 已知限制与待确认

第二阶段已接入 4 号查询/统计/导出，并新增统计导出端点；以下仍未闭环，已在 `docs/10_任务台账.md` 登记：

1. **结转流水展示**：计划页已显示 `carry_in`/`quota_total`（计划级），但完整 `carry_log` 流水仍无端点；运行控制暂不展示逐条结转。
2. **按初中 / 高中—批次查名单及余额**：当前只有计划名单与学校统计，缺初中维度和高中—批次名单。
3. **统计导出契约**：`GET /api/export/stats.csv` 已实现，需 1 号在 `docs/00_契约.md` 第 6 节登记为正式端点。
4. **基础数据管理**：任务书要求录入、修改、导入、校验；当前由 2 号脚本承担，页面只有“新建运行/装载数据”。
5. **两例滑档案例**：页面支持任意两 run 对比，需 5 号提供两对 `run_id` 与考生编号。
6. **真实投档写入**：`write_results` 仍是 `NotImplementedError`（2 号 W2 预留、3 号未实现），真实 `/execute` 返回 501。
7. **15 万性能**：2 号 large 生成分支尚未合入；4 号统计目前在线聚合，需在 15 万数据下测响应时间，必要时补汇总表/索引。

其他限制：

- 页面只读 4 号接口，不直连数据库，不在前端计算梯度、名额、最低分、末位考生。
- SQLite 单文件、单机演示，无鉴权、无并发写入。
- mock 数据只用于联调，演示成片必须使用真实模式。
- 15 万数据与视频不入库，按 `deploy/README.md` 重新生成或拷贝。
