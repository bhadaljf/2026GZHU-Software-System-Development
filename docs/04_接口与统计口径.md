## 2 查询维度

| 维度 | 入口函数 | 过滤/分页 | 端点（6 号挂） |
| --- | --- | --- | --- |
| 考生 | `query.student.get_student_result` | 按考生编号；返回全部志愿判定 | `GET /api/students/{sid}/result?run_id=` |
| 高中 | `query.stats.get_school_stats` | 按 `high_school.school_id` | `GET /api/stats/school/{sid}?run_id=` |
| 初中 | `query.student.get_student_result` 返回 `junior_school`；二批名额按“高中—初中”看 `plan_id` + `quota_plan` | 按考生所属初中 | 见契约第 1 节 |
| 批次 | `query.stats.get_batch_stats` / `get_score_distribution` | 批次 1—4 | `GET /api/stats/batch/{batch}`、`GET /api/distribution/{batch}` |
| 计划 | `query.plan.get_plan_admissions` | 按计划编号，`page`/`size` 分页 | `GET /api/plans/{pid}/admissions?run_id=&page=&size=` |

排序约定：志愿按 `batch, seq` 升序；录取名单按 `admit_order` 升序；分数段按 `low` 降序；按校统计按录取数降序。

## 3 接口字段

函数签名与 `docs/09_接口清单.md` 第 3 节一致，末尾新增可选关键字参数 `conn=None`（复用调用方连接）、`mock=None`（强制 mock），属只增不改。

### 3.1 `get_student_result(run_id, student_id)`

```json
{
  "run_id": "RUN20261210-01", "student_id": "S01", "exists": true,
  "name": "甲", "junior_school_id": "M01", "junior_school": "M 一中",
  "score": 690, "tie_seq": 1,
  "admitted": true, "batch": 3, "plan_id": "P-A3", "school": "A 校",
  "volunteer_no": 1, "admit_order": 1,
  "reason_code": null, "reason_text": null,
  "volunteers": [
    {"batch": 3, "seq": 1, "plan_id": "P-A3", "status": "admitted", "reason_code": null, "reason_text": null},
    {"batch": 3, "seq": 2, "plan_id": "P-B3", "status": "skipped", "reason_code": "R02", "reason_text": "计划名额已满"},
    {"batch": 4, "seq": 1, "plan_id": "P-E4", "status": "skipped", "reason_code": "R04", "reason_text": "前批已录取"}
  ]
}
```

- 未录取：`admitted=false`，`batch`/`plan_id`/`school`/`volunteer_no`/`admit_order` 全为 `null`，未录原因取**最后一个被跳过志愿**的 `reason_code`（R34）。
- `status` 取值：`admitted` / `skipped` / `pending`（该志愿在日志里没有判定记录，说明没跑到或数据缺失，便于对账时暴露问题）。
- 考生不存在：`exists=false`，其余字段为 `null`/空数组，6 号据此返回 404。

### 3.2 `get_plan_admissions(run_id, plan_id, page=1, size=100)`

```json
{
  "plan_id": "P-A3", "exists": true, "school": "A 校", "batch": 3, "category": "unified",
  "control_line": 492, "quota": 2, "carry_in": 0, "quota_total": 2,
  "admitted_count": 2, "remaining": 0,
  "min_score": 690, "max_score": 710,
  "last_admitted": {"student_id": "S02", "score": 710, "tie_seq": 1, "volunteer_no": 2, "admit_order": 2},
  "items": [{"admit_order": 1, "student_id": "S01", "score": 690, "tie_seq": 1, "volunteer_no": 1},
            {"admit_order": 2, "student_id": "S02", "score": 710, "tie_seq": 1, "volunteer_no": 2}],
  "page": 1, "size": 100, "total": 2, "total_pages": 1
}
```

- `quota_total = quota + carry_in`（R27）；`remaining` 优先取 `plan.remaining`，该列为空时才用 `quota_total − admitted_count` 兜底。
- `min_score` 与 `last_admitted` **分别计算**，上例最低分是甲（690）、末位是乙（710），不是同一人（R30、R31）。
- 无人录取：`min_score`、`last_admitted`、`max_score` 均为 `null`，界面显示“无”，**不得返回 0**（R32）。
- 分页：`page < 1` 纠正为 1；`size` 限制在 1—500，默认 100；`total_pages` 至少为 1。

### 3.3 `get_batch_stats(run_id, batch)`

返回：`plan_count`（计划条数）、`quota_total`（有效计划数）、`admitted_count`、`completion_rate`（0—1 小数）、`completion_rate_text`（如 `"75.00%"`）、`unfilled_quota`、`remaining_quota`、`unfilled_plans`、`min_score`、`max_score`、`volunteered_students`（该批填报人数，按人去重）、`unadmitted_students`（填报该批但本批未录的人数）、`plans`（逐计划摘要）。

### 3.4 `get_school_stats(run_id, school_id)`

返回：`school`、`exists`、`overall`（全校总体）、`by_batch`（分批）、`by_category`（分类：自主招生/名额分配/统招）、`plans`（逐计划）。**三套口径分开算，不混算完成率**（R33）。

### 3.5 `get_score_distribution(run_id, batch, bucket_size=10)`

返回：`bucket_size`、`buckets`（`label`/`low`/`high`/`count`，按分段降序）、`total`、`min_score`、`max_score`、`lines`（参考线：控制线 L、第一梯度线 G₁、梯度差 Δ，取自 `config/rules.toml`，读不到为 `null`）。统计对象是**该批已录考生**。

### 3.6 `query.reasons`

`REASON_CODES`、`describe(code)`、`codes()`、`all_reasons()`（返回 `[{code, text, batches}]`）、`is_valid(code)`。空码 `describe` 返回 `"-"`，未知码返回 `"未知原因"`（不抛异常，便于对账暴露脏数据）。

### 3.7 `report.build_stats_report(run_id)`

返回 `run`（运行快照）、`overall`（含 `volunteered_students`、`admitted_students`、`unadmitted_students`、`admit_rate`）、`by_batch`、`by_category`、`by_school`、`conservation`（R27 逐计划守恒核对，只回前 20 条不一致）、`notes`（口径条目）。供 1 号报告取数；正式审计仍以 1 号 `src/check_metrics.py` 为准。

### 3.8 导出 `export.export_csv`

| 函数 | 默认输出 | 列 |
| --- | --- | --- |
| `export_admissions(run_id)` | `export/录取结果_{run_id}.csv` | 运行编号, 考生编号, 姓名, 初中, 批次, 批次类别, 计划编号, 高中, 录取总分, 同分序号, 志愿序号, 录取顺序 |
| `export_stats(run_id)` | `export/统计汇总_{run_id}.csv` | 维度, 对象, 计划数, 有效计划数, 录取数, 完成率, 未完成名额, 未完成计划数, 最低录取分, 最高录取分 |

编码 UTF-8 with BOM；每次导出同时生成 `*_口径说明.md`（含 run_id、生成时间、行数、口径条目），满足 R35“导出含口径说明”。

## 5 统计口径

1. **最低录取分**＝该计划已录考生总分的最小值（`MIN(admit_result.score)`），单独字段（R30）。
2. **末位考生**＝按实际录取顺序最后录取者（`admit_order` 最大），另报总分、志愿序号、同分序号（R31）。
3. 二者分别计算，**可以为不同人**；不得用末位考生分数代替最低分，也不得把最低分考生当末位。
4. 无人录取：二者与 `max_score` 均为 `null`，界面显示“无”，禁止 0 分（R32）。
5. **完成率**＝已录人数／有效计划数，有效计划数＝初始计划＋转入（`plan.quota + carry_log.amount`）；除数为 0 时按 0 处理。
6. **未完成名额**＝`max(有效计划数 − 已录, 0)`；**未完成计划**＝剩余名额 > 0 的计划条数。
7. 学校总体、分批、分类三套口径分开算（R33）；三批与四批不合并算完成率（R28，三四批余缺各自保留）。
8. 分数分布按已录考生的 `admit_result.score` 快照统计，不取考生当前分数。
9. 所有分数为整数；空值一律 `null`（JSON）/“无”（界面与 CSV）。

## 5.2 统计汇总表与索引（第二阶段：统计改读汇总表）

15 万条明细不适合每次在线聚合，第二阶段按 `docs/07` 的要求改为“优先读汇总表”：

| 事项 | 约定 |
| --- | --- |
| 表名 | `plan_summary`，DDL 见 `src/query/perf.py` 的 `summary_ddl()`；**2 号建表与刷新，4 号只读** |
| 粒度 | 一行 = 一个 `(run_id, plan_id)`，含 `quota_total`、`admitted_count`、`remaining`、`min_score`、`max_score` 与末位考生快照 `last_*` |
| 刷新时机 | 3 号 `store.write_results` 写完成绩后刷新；未执行的批次也要写 `admitted_count = 0` 的行 |
| 完整性校验 | 汇总行数必须等于该 run 年度 `plan` 的行数，否则整表按“不可用”处理 |
| 回退 | 表不存在 / 该 run 无行 / 行数不足 / 按批或按校过滤后为空，一律回退在线聚合：结果不变，只慢一点 |
| 来源标记 | `get_batch_stats`、`get_school_stats`、`get_score_distribution` 额外返回 `source`：`summary` / `online` / `mock` |

`source` 是排查“统计为什么不对”的第一现场：出现 `online` 说明汇总表没刷全，先找 2 号/3 号，**不要在这里改口径**。

| 索引 | 字段 | 服务的查询 |

| `idx_admit_result_run_plan_order` | `admit_result (run_id, plan_id, admit_order)` | 计划名单、最低分、末位考生 |
| `idx_admit_result_run_student` | `admit_result (run_id, student_id)` | 考生去向 |
| `idx_admit_result_run_batch` | `admit_result (run_id, batch)` | 批次统计、分数分布 |
| `idx_admit_log_run_student` | `admit_log (run_id, student_id)` | 未录原因码 |
| `idx_volunteer_student_year` | `volunteer (student_id, year, batch, seq)` | 志愿处理情况 |
| `idx_plan_school_batch` | `plan (high_school_id, batch)` | 学校/批次统计 |

## 6 首版联调说明（mock 模式）

第 1 阶段 2 号建表、3 号引擎未交付时，本模块可独立跑：

- 判断顺序：显式入参 `mock` > 环境变量 `ZKS_MOCK`（`1` 强制假数据 / `0` 强制真库）> 库是否可用（`data/app.db` 存在且 `student`/`plan`/`admit_result`/`admit_log`/`volunteer` 五张表齐全才算可用）。
- 库不可用时自动返回 `src/query/mockdata.py` 的假数据，形状与 `docs/08_协作规范与样例.md` 第 6 节一致（P-A3 最低分 690、末位 S02/710；P-G3 无人录取返回 `null`），返回值额外带 `"_mock": true` 供 6 号提示“演示数据”。
- 2 号、3 号交付后**什么都不用改**：库一建好，同一个函数自动走真实数据；也可以 `ZKS_MOCK=0` 强制真库，验证“库缺失时报错而不是静默返回假数据”。
- 4 号只读：`src/query/__init__.connect()` 默认用只读 URI 打开（`mode=ro`），误写会直接报错。
