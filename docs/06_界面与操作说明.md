# 06_界面与操作说明

负责人：6 号　版本：v0.2（2026-11-21，第 1 阶段）
读者：任课教师、组内成员、演示讲解人。

本文件说明系统的启动方式、界面布局、五个区块中**每一个控件的作用与操作结果**、字段口径和常见错误。页面本身只做展示，不计算投档规则；所有数据来自 `src/api/main.py` 暴露的 11 个端点。

## 1 启动与访问

### 1.1 环境

- Python 3.11 及以上；依赖 `fastapi`、`uvicorn`（安装见 `deploy/README.md`）。
- 浏览器：Chrome / Edge 最新版。

### 1.2 mock 模式（第 1 阶段联调、无数据库）

```powershell
# Windows PowerShell
$env:API_MOCK="1"; python -m uvicorn src.api.main:app --reload --port 8000
```

```bash
# Git Bash / macOS / Linux
API_MOCK=1 python -m uvicorn src.api.main:app --reload --port 8000
```

浏览器打开 `http://127.0.0.1:8000`。mock 模式使用 `src/api/mocks.py` 的假数据，固定两个运行编号：

- `RUN20261121-01`：调整前；
- `RUN20261121-02`：调整后。

### 1.3 真实模式（2/3/4 号模块就绪后）

```bash
python -m uvicorn src.api.main:app --reload --port 8000
```

真实模式不会回退假数据；某个端点依赖的模块未就绪时返回 501，页面用提示条显示“依赖未就绪: 模块名”。

### 1.4 访问方式

必须通过 `http://127.0.0.1:8000` 访问，不要直接双击 `interface/index.html` 用 `file://` 打开——页面能显示，但 `js/api.js` 请求不到后端。

### 2.3 推荐操作顺序

1. 运行控制：新建运行 → 完整运行（或按批执行）→ 看进度与余额。
2. 考生查询：查某考生的去向与每个志愿的处理原因。
3. 计划与名单：查某计划的名单、余额、最低分、末位考生。
4. 统计：查批次统计、分数分布、学校统计，导出 CSV。
5. 案例对比：同一考生调整志愿前后两次运行的左右对照。

## 3 区块 01：运行控制

### 3.1 用途

创建一次模拟运行、选择数据规模、执行全部或指定批次、查看运行进度和各批计划余额。

### 3.2 控件逐一说明

| 控件 | 位置 | 作用 | 操作与结果 | 调用端点 |
| --- | --- | --- | --- | --- |
| 数据规模 | 运行参数面板左侧 | 选择本次运行使用小数据集还是 15 万规模数据 | 下拉选项“小数据集 / 15 万”；只在下一次点“新建运行”时生效，不会改变已创建运行 | `POST /api/runs` 的 `scale` |
| 批次 | 运行参数面板 | 选择“执行所选批次”要执行的批次 | 下拉 1—4，分别对应自主招生、名额分配、第三批统招、第四批统招 | `POST /api/runs/{run_id}/execute` 的 `batches` |
| 新建运行 | 运行参数面板右侧 | 创建一个运行编号，作为后续查询、执行、导出的依据 | 成功：顶部状态变为“运行 RUN…”，运行提示显示“已创建运行 RUN…（小数据集/15 万）”，`run_id` 写入 `localStorage`。失败：提示条显示 400/501 | `POST /api/runs` |
| 完整运行（1—4 批） | 运行参数面板右侧（蓝色） | 按第一至第四批顺序执行完整投档 | 成功：进度条走到 100%，运行提示“运行 RUN… 已完成”，余额表刷新。未新建运行：提示“请先在‘运行控制’新建运行” | `POST /api/runs/{run_id}/execute`，`batches=[1,2,3,4]` |
| 执行所选批次 | 运行参数面板右侧 | 只执行“批次”下拉选中的那一批 | 成功：进度显示该批完成，余额表显示该批余额（mock）。未新建运行：提示先新建运行 | `POST /api/runs/{run_id}/execute`，`batches=[选中批次]` |
| 运行进度条 | 运行进度面板 | 直观显示完成比例 | 阶段为“已完成”时 100%；“执行中”按 `done/total` 计算；失败时停在当前值 | `GET /api/runs/{run_id}/progress` |
| 进度文字 | 进度条下方 | 显示阶段、完成数/总数、百分比、失败详情 | 初始“阶段：未开始　进度：0/0（0%）”；完成后例：“阶段：已完成　进度：4/4（100%）” | 同上 |
| 运行提示 | 运行参数面板底部 | 显示当前运行的状态说明 | 初始“尚未创建运行”；刷新恢复显示“当前运行 RUN…”；新建后“已创建运行…”；执行中“正在执行批次…”；完成“运行 RUN… 已完成”；失败“运行 RUN… 失败：详情” | 前端状态 + 执行/进度端点 |
| 各批余额表 | 运行进度面板下方 | 展示每批计划数、已录人数、剩余名额 | 列为“批次 / 计划数 / 已录 / 余额”；无数据显示“无数据”；空值显示“无”。mock 有四批样例；真实模式当前 `balances` 为空，待 3/4 号补齐 | `GET /api/runs/{run_id}/progress` 的 `balances` |

### 3.3 操作步骤

1. 选“数据规模”（默认小数据集）。
2. 点“新建运行”，确认顶部状态出现 `运行 RUN…`。
3. 点“完整运行（1—4 批）”；或先选“批次”，再点“执行所选批次”。
4. 观察进度条、进度文字和余额表；完成后再去 02—05 查询。

### 3.4 边界与错误

- 没新建运行就点执行：提示“请先在‘运行控制’新建运行”。
- 刷新页面：`run_id` 从 `localStorage` 恢复，顶部与运行提示显示当前运行；余额表/分数分布显示“无数据”，重新执行或查询后才有内容。
- mock 模式重复点“新建运行”：始终返回 `RUN20261121-01`，便于刷新后继续演示。
- 真实模式：`run_id` 由 `run_meta.create_run` 递增；数据库不存在时先 `store.init_db`。
- 真实模式依赖未就绪：提示 `501 依赖未就绪: src.store`（或具体模块）。
- 执行中重复点击：按钮在请求期间禁用，不会重复提交。
- 进度轮询：页面每 800ms 调一次 `GET /api/runs/{run_id}/progress`，阶段为 `done` 或 `error` 时停止。

## 4 区块 02：考生查询

### 4.1 用途

输入考生编号，查看其录取去向、每个志愿的处理状态和未录取原因。

### 4.2 控件逐一说明

| 控件 | 位置 | 作用 | 操作与结果 | 调用端点 |
| --- | --- | --- | --- | --- |
| 考生编号输入框 | 查询面板 | 输入要查询的考生编号 | 占位提示“如 S01”；按 Enter 等同点“查询” | — |
| 查询按钮 | 输入框右侧（蓝色） | 查询该考生在当前运行下的结果 | 成功：下方出现结果卡。失败：404 提示“考生不存在或该运行无结果”；未新建运行提示先新建 | `GET /api/students/{sid}/result?run_id=` |
| 结果卡 | 查询面板下方 | 显示考生基本信息与录取结论 | 字段：考生、总分、同分序号、是否录取、录取批次、录取计划、学校、志愿序号、录取顺序；未录取时批次/计划/学校/志愿序号/录取顺序显示“无” | 同上 |
| 志愿处理列表 | 结果卡下半部分 | 逐条显示每个志愿的处理情况 | 每行格式“批次 X 志愿 Y：计划编号　录取/跳过　原因码 + 中文”；录取志愿的原因显示“—”；未录取志愿显示 R01—R07 | 同上 |

### 4.3 操作步骤

1. 确认顶部已显示 `运行 RUN…`；没有则先到 01 新建运行。
2. 输入考生编号（mock 可用 S01、S02、S03、S09）。
3. 点“查询”或按 Enter。
4. 看“是否录取”和各志愿的“录取/跳过 + 原因”。

### 4.4 边界与错误

- 未新建运行：提示“请先在‘运行控制’新建运行”。
- 考生不存在：`404 考生不存在: S99`。
- 未录取考生：结果卡中录取字段全部显示“无”，原因写在对应志愿行。
- 原因码含义见第 8.2 节。

## 5 区块 03：计划与名单

### 5.1 用途

输入计划编号，查看该计划的名额、已录人数、余额、最低录取分、末位考生和录取名单，并分页浏览。

### 5.2 控件逐一说明

| 控件 | 位置 | 作用 | 操作与结果 | 调用端点 |
| --- | --- | --- | --- | --- |
| 计划编号输入框 | 查询面板 | 输入要查询的计划编号 | 占位“如 P-A3”；按 Enter 等同点“查询” | — |
| 每页条数 | 查询面板 | 选择每页显示多少条名单 | 20 / 50 / 100，默认 50；改变后若已有计划编号，自动回到第 1 页重查 | 请求参数 `size` |
| 查询按钮 | 查询面板右侧（蓝色） | 查询该计划 | 成功：出现汇总卡和名单表。失败：404 提示“计划不存在” | `GET /api/plans/{pid}/admissions?run_id=&page=&size=` |
| 汇总卡 | 查询面板下方 | 显示计划级统计与口径 | 字段：计划、名额、已录、余额、最低录取分、末位考生、完成情况。末位考生格式“考生（总分 分，志愿 X，同分序号 Y）”；无人录取时最低分和末位考生显示“无” | 同上 |
| 录取名单表 | 汇总卡下方 | 按录取顺序列出名单 | 列：录取顺序、考生、总分、志愿序号、同分序号；无数据显示“无数据” | 同上 |
| 上一页 | 名单表下方 | 回到上一页 | 第 1 页时禁用 | `page-1` |
| 页码信息 | 分页中间 | 显示当前页、总页数、总条数 | 例：“第 2 / 3 页，共 120 条” | 返回的 `page`、`total` |
| 下一页 | 名单表下方 | 进入下一页 | 最后一页时禁用 | `page+1` |

### 5.3 操作步骤

1. 确认已有运行编号。
2. 输入计划编号（mock 可用 P-A3、P-B3、P-LARGE）。
3. 点“查询”或按 Enter。
4. 先看汇总卡的口径，再用上一页/下一页翻名单；P-LARGE 有 120 条，可验证三页分页。

### 5.4 口径与边界

- 最低录取分＝该计划已录考生总分的最小值；末位考生＝按实际录取顺序最后录取者，两者分别计算，可能不是同一人。
- 无人录取：`min_score` 与 `last_admitted` 都显示“无”，不得显示 0。
- 未完成计划：余额大于 0 时“完成情况”显示“未完成”；不为了凑满额降低分数线。
- 计划不存在：`404 计划不存在: P-X`。
- 每页最多 200 条（后端校验），页面只提供 20/50/100。

## 6 区块 04：统计

### 6.1 用途

查看批次统计、学校统计、分数分布，并导出录取明细 CSV。

### 6.2 控件逐一说明

| 控件 | 位置 | 作用 | 操作与结果 | 调用端点 |
| --- | --- | --- | --- | --- |
| 批次下拉 | 批次统计面板 | 选择统计批次 | 1—4，默认 3 | — |
| 查询批次统计 | 批次统计面板（蓝色） | 查该批计划数、录取数、完成率、未录取人数、最低分 | 成功：下方统计卡出现。失败：400/501 提示 | `GET /api/stats/batch/{batch}?run_id=` |
| 查询分数分布 | 批次统计面板 | 查该批各分数段人数 | 成功：批次统计卡下方的“分数分布”表刷新 | `GET /api/distribution/{batch}?run_id=` |
| 导出录取 CSV | 批次统计面板 | 下载当前运行的录取明细 | 浏览器下载 `admit_RUN….csv`（UTF-8 带 BOM，Excel 可直接打开）；未新建运行提示先新建 | `GET /api/export/admissions.csv?run_id=` |
| 批次统计卡 | 批次统计面板下方 | 显示批次级统计 | 字段：批次、计划数、录取数、完成率、未录取、最低录取分；完成率显示为百分比，无人录取的最低分显示“无” | 批次统计端点 |
| 学校编号输入框 | 学校统计面板 | 输入要查的学校编号 | 占位“如 H-A”；按 Enter 等同点“查询学校统计” | — |
| 查询学校统计 | 学校统计面板（蓝色） | 查该校总体统计 | 成功：下方学校统计卡出现；404 提示学校不存在 | `GET /api/stats/school/{sid}?run_id=` |
| 学校统计卡 | 学校统计面板下方 | 显示学校总体统计 | 字段：学校、计划数、录取数、完成率、未录取、最低录取分、末位考生 | 同上 |
| 分数分布表 | 批次统计卡下方 | 显示分数段与人数 | 列为“分数段 / 人数”；无数据显示“无数据” | 分布端点 |

### 6.3 操作步骤

1. 确认已有运行编号。
2. 选批次 → “查询批次统计” → 看统计卡。
3. 点“查询分数分布” → 看下方表。
4. 输入学校编号（mock 可用 H-A、H-B）→ “查询学校统计”。
5. 点“导出录取 CSV”下载明细。

### 6.4 口径与边界

- 完成率：后端返回 0—1 小数时按百分比显示并保留 1 位（如 0.9375 → 93.8%）；返回 0 显示“0.0%”，不显示“无”；返回 null 显示“无”。
- 无人录取的批次/学校：最低录取分、末位考生显示“无”。
- 批次 4 的 mock 数据故意设为“计划 20、录取 0、最低分无”，用于演示空结果口径。
- 统计与明细分开：批次统计、学校统计、分数分布是三张不同的卡/表，不混算。
- 导出只有录取明细，不含统计汇总；统计 CSV 端点尚未提供（见第 10 节）。

## 7 区块 05：案例对比

### 7.1 用途

对同一考生，比较“调整志愿前”和“调整志愿后”两次运行的结果，观察录取去向、志愿状态和原因码的变化。用于滑档案例讲解。

### 7.2 控件逐一说明

| 控件 | 位置 | 作用 | 操作与结果 | 调用端点 |
| --- | --- | --- | --- | --- |
| 考生编号 | 对比面板 | 要对比的考生 | 默认 `S01`；按 Enter 等同点“对比” | — |
| 调整前 run_id | 对比面板 | 第一次运行的编号 | 默认 `RUN20261121-01`（mock 调整前） | — |
| 调整后 run_id | 对比面板 | 第二次运行的编号 | 默认 `RUN20261121-02`（mock 调整后） | — |
| 对比按钮 | 对比面板右侧（蓝色） | 同时查两次运行下该考生的结果 | 成功：左右两栏出现。任一运行查不到该考生：404 提示 | `GET /api/students/{sid}/result?run_id=`（调用两次） |
| 左栏“调整前” | 面板下方左侧 | 显示第一次运行的结果 | 字段：考生、总分、是否录取、录取批次、录取计划、志愿序号；下方逐志愿显示状态与原因 | 第一次调用 |
| 右栏“调整后” | 面板下方右侧 | 显示第二次运行的结果 | 同上 | 第二次调用 |
| 差异高亮 | 两栏志愿列表 | 标出两次运行中计划、状态或原因码发生变化的志愿 | 变化行浅黄底、左侧橙色竖线；未变化行无底色 | 前端对比 |

### 7.3 操作步骤

1. 确认两次运行都已存在（mock 模式默认即可）。
2. 输入考生编号与两个 run_id。
3. 点“对比”。
4. 先看左右两栏的“是否录取/录取计划”，再逐志愿看状态与原因变化；黄色行就是差异。

### 7.4 边界与错误

- mock 模式固定 `RUN20261121-01` / `RUN20261121-02`；`S01` 在调整前录取 P-A3，调整后未录取（P-B3 与 P-A3 均显示 R02 名额已满），用于演示。
- 真实模式由 5 号提供两套数据与两次运行的 `run_id`；页面不负责创建这两次运行。
- 任一 run_id 不存在或该考生无结果：`404` 提示。
- 只需对比一个考生；多考生案例重复操作即可。

### 8.1 字段来源

| 同分序号 | `tie_seq` | 越小越优先 |

### 8.2 原因码

| 码 | 页面文案 | 适用批次 |
| --- | --- | --- |
| R01 | 未达计划控制线或最低控制线 L | 全部 |
| R02 | 计划名额已满 | 全部 |
| R03 | 不在自主招生资格名单或排名不达 | 第一批 |
| R04 | 前批已录取 | 第二至第四批 |
| R05 | 非所属初中名额 | 第二批 |
| R06 | 志愿或计划无效 | 全部 |
| R07 | 未填报该计划 | 全部 |

原因码由 `renderReason` 转为“码 + 中文”；码表以 `docs/00_契约.md` 第 3 节为准，4 号 `all_reasons()` 就绪后以其文案为准。

### 8.3 空值与状态

- 分数、余额、批次、计划、学校、志愿序号、录取顺序、最低录取分、末位考生为 `null` 时一律显示“无”，不得写 0（R32）。
- `0` 是有效值：录取数 0 显示“0”，完成率 0 显示“0.0%”，不显示“无”。
- 志愿状态 `admitted` 显示“录取”，`skipped` 显示“跳过”；未录取志愿的原因显示 R01—R07。
- 未完成计划：余额大于 0 时“完成情况”显示“未完成”。
- 空值与“无”只在 `interface/js/render.js` 的 `renderScore` / `renderKV` 处理，页面脚本不自行判断。

### 8.4 分页

- 计划名单每页 20 / 50 / 100 条，默认 50；翻页只请求当前页，不一次渲染全表。
- 15 万规模数据下禁止一次渲染全部行；`page` 从 1 开始，`size` 上限 200。
- 第 1 页禁用“上一页”，最后一页禁用“下一页”。

## 9 常见错误与处理

| 页面现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 提示 `501 依赖未就绪: src.store`（或 `src.query.*`、`src.engine.runner`） | 真实模式下 2/3/4 号模块还没交付 | 用 `API_MOCK=1` 联调；或等模块就绪后重启服务 |
| 提示 `404 考生不存在` / `404 计划不存在` / `404 学校不存在` | 编号拼错，或该运行下没有这个对象 | 核对编号；mock 可用 S01—S04/S09、P-A3/P-B3/P-LARGE、H-A/H-B |
| 提示 `404 运行不存在` | `run_id` 不属于当前数据库 | 重新“新建运行”，用新编号 |
| 提示 `422` | 请求缺少 `run_id` 等必填参数 | 正常通过页面操作不会出现；检查是否直接调用了端点 |
| 结果一直“无数据” | 还没执行投档，或运行编号不对 | 回到 01 执行完整运行/对应批次 |
| 页面打开是空白/按钮无反应 | 用 `file://` 打开了 `index.html`，或服务没启动 | 用 `http://127.0.0.1:8000` 访问，确认 uvicorn 在运行 |
| 导出没有反应 | 浏览器拦截下载，或未新建运行 | 允许本站下载；先新建运行 |
| 刷新后查询提示先新建运行 | 浏览器清除了 `localStorage` | 重新“新建运行” |
| 真实模式余额表为空 | 当前 `/progress` 的 `balances` 还没由 3/4 号提供 | mock 模式有样例；真实模式待联调补齐 |

## 10 已知限制与待确认

当前 11 个端点覆盖不到任务书的以下要求，已在 `docs/10_任务台账.md` 的“阻塞与跨人依赖”登记：

1. **结转情况展示**：`carry_log` 无端点，运行控制目前只展示余额；建议在 `progress` 增加 `carry` 字段或新增端点。
2. **按初中 / 高中—批次查名单及余额**：当前只有计划名单与学校统计，缺初中维度和高中—批次名单。
3. **统计导出**：目前只有录取明细 CSV，统计汇总 CSV 无端点。
4. **基础数据管理**：任务书要求录入、修改、导入、校验；当前由 2 号脚本承担，页面只有“新建运行/装载数据”。
5. **两例滑档案例**：页面支持任意两 run 对比，但需 5 号提供两对 `run_id` 与考生编号。

其他限制：

- 页面只读 4 号接口，不直连数据库，不在前端计算梯度、名额、最低分、末位考生。
- SQLite 单文件、单机演示，无鉴权、无并发写入。
- mock 数据只用于联调，演示成片必须使用真实模式。
- 15 万数据与视频不入库，按 `deploy/README.md` 重新生成或拷贝。
