## 1 页面清单

| 区块 | 用途 | 调用端点 | 关键字段 |
| --- | --- | --- | --- |
| 运行控制 | 新建运行、完整/按批执行、进度与各批余额 | `POST /api/runs`、`POST /api/runs/{run_id}/execute`、`GET /api/runs/{run_id}/progress` | `run_id`、`stage`、`done`、`total`、`balances[batch/quota/admitted/remaining]` |
| 考生查询 | 查去向、各志愿处理与未录原因 | `GET /api/students/{sid}/result?run_id=` | `student_id`、`score`、`tie_seq`、`admitted`、`batch`、`plan_id`、`school`、`volunteer_no`、`admit_order`、`volunteers[]` |
| 计划与名单 | 名单、余额、最低分、末位考生、分页 | `GET /api/plans/{pid}/admissions?run_id=&page=&size=` | `quota`、`admitted_count`、`remaining`、`min_score`、`last_admitted`、`items[]`、`page/size/total` |
| 统计 | 批次/学校统计、分数分布、导出 | `GET /api/stats/batch/{batch}`、`GET /api/stats/school/{sid}`、`GET /api/distribution/{batch}`、`GET /api/export/admissions.csv` | `plan_count`、`admitted_count`、`fill_rate`、`unadmitted_count`、`min_score`、`buckets[]` |
| 案例对比 | 同一考生调整志愿前后两次运行对比 | `GET /api/students/{sid}/result?run_id=`（调用两次） | 同考生查询；左右两列逐志愿对照 |

当前 11 个端点未覆盖任务书的结转情况、按初中/高中—批次查名单、统计导出与数据管理；已在 `docs/10_任务台账.md` 的“阻塞与跨人依赖”登记，待 1 号确认是否走契约变更，页面不擅自加接口。

## 2 操作流程

1. 启动服务：`uvicorn src.api.main:app --reload`，浏览器打开 `http://127.0.0.1:8000`。
2. 运行控制：选数据规模 → “新建运行” → “完整运行（1—4 批）”或选定批次后“执行所选批次”；页面显示进度、各批计划数、已录与余额。
3. 考生查询：输入考生编号，查看是否录取、批次、计划、志愿序号、录取顺序，以及每个志愿的录取/跳过与原因码。
4. 计划与名单：输入计划编号，查看名额、已录、余额、最低录取分、末位考生与名单；用上一页/下一页翻页。
5. 统计：选批次查计划数、录取数、完成率、未录取人数、最低分；输入学校编号查学校总体统计；查分数分布；点“导出录取 CSV”下载。
6. 案例对比：输入考生编号与调整前/后两个 `run_id`，左右两列逐志愿对照，状态或原因变化的行高亮。

## 3 字段与显示规则

### 3.1 字段来源

| 界面标签 | 接口字段 | 来源/口径 |
| --- | --- | --- |
| 总分 | `score` | `student.score`，整数 |
| 同分序号 | `tie_seq` | `student.tie_seq`，越小越优先（R16） |
| 是否录取 | `admitted` | 结果表是否有该考生记录 |
| 录取批次 | `batch` | `admit_result.batch` |
| 录取计划 | `plan_id` | `admit_result.plan_id` |
| 学校 | `school` | 计划所属高中名称 |
| 志愿序号 | `volunteer_no` | 被录志愿序号 |
| 录取顺序 | `admit_order` | 该计划内从 1 连续编号 |
| 名额 | `quota` | `plan.quota`（初始计划） |
| 已录 | `admitted_count` | 该计划录取人数 |
| 余额 | `remaining` | `plan.remaining`（R29） |
| 最低录取分 | `min_score` | 已录考生总分最小值（R30） |
| 末位考生 | `last_admitted` | 按实际录取顺序最后录取者（R31） |
| 完成率 | `fill_rate` | 已录 / 计划数 |
| 未录取 | `unadmitted_count` | 未录取人数 |
| 分数分布 | `buckets[].label/count` | 分数段 → 人数 |
| 原因码 | `reason_code` | R01—R07，见契约第 3 节 |

### 3.2 空值与“无”

- 分数、余额、批次、计划、学校等字段为 `null` 时一律显示“无”，不得写 0（R32）。
- 无人录取的计划：`min_score` 与 `last_admitted` 分别显示“无”；二者分别计算，可能不是同一人。
- 未完成计划：显示已录人数与余额，并标注“未完成”；不为了凑满额降低分数线（R19）。
- 空值与“无”只在 `interface/js/render.js` 的 `renderScore` / `renderKV` 处理，页面脚本不自行判断。

### 3.3 原因码与状态

- 原因码显示为“码 + 中文”，如 `R02 计划名额已满`；码表以契约第 3 节为准，文案由 4 号 `all_reasons()` 提供。
- 志愿状态 `admitted` / `skipped` 显示为“录取” / “跳过”；未经 `renderReason` 不直接展示机器码。

### 3.4 分页

- 计划名单每页 20 / 50 / 100 条可选，默认 50；翻页只请求当前页，不一次渲染全表。
- 15 万规模数据下禁止一次渲染全部行；分页参数 `page` 从 1 开始，`size` 上限 200。
