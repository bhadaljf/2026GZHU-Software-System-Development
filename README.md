# 简化广州中考公办高中录取模拟系统

软件系统开发实践课程设计 · 6 人组 · 4 个自然周（2026.11.16—12.13，周日为阶段验收截止日）

仓库于 2026.11.19 建立；项目排期按课程自然周执行，不以建仓日期重新起算。

按任务书简化规则实现四批次投档：梯度优先、同梯度志愿优先、名额分配到校、剩余计划结转。输入的虚构数据可复现，输出为录取结果、投档日志与统计报表。

## 技术栈与选型理由

任务书未规定形态，只要求“包含前后端”“关键界面”“操作流程”，并说明选择理由。本项目做成**网页系统**。

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 形态 | 网页（单页 + 后端 API） | 浏览器直接演示与录屏，无需安装客户端、无需打包签名；评审可按 URL 与操作流程复现 |
| 前端 | 原生 HTML/CSS/JS（`interface/`） | 无构建链，改了刷新即可，六人并行时不互相卡 Node 版本；页面只渲染 JSON |
| 后端 | Python 3.11 + FastAPI（`src/api/`） | 与引擎、测试同语言；自带接口文档，便于 4 号与 6 号按端点对齐 |
| 数据库 | SQLite（单文件） | 15 万考生 + 约 75 万志愿在单机足够；交付与复现只需拷一个文件，部署说明最短 |
| 测试 | pytest（`test/auto/`） | 小数据集可一键重跑，对账结论可复现 |
| 启动 | `uvicorn src.api.main:app` | 一条命令起服务，浏览器打开 127.0.0.1 即用 |

取舍：若后续确需移动端，可把 `interface/` 换成响应式页面或包一层 Capacitor，后端端点不变；若数据量再上一个量级，再把 SQLite 换 PostgreSQL，`src/store.py` 是唯一改动点。

配置格式用 TOML（`config/rules.toml`），由 Python 3.11 标准库 `tomllib` 直接读取，不引入 PyYAML。建库顺序为 `db/schema.sql` → `db/schema_run.sql` → `db/schema_log.sql`，`run` 表只在 `schema_run.sql` 定义一份。

## 快速开始

环境、依赖、建库、数据装载与真实模式说明见 `deploy/README.md`。页面演示可直接用 mock 模式：

```bash
# Git Bash / macOS / Linux
API_MOCK=1 python -m uvicorn src.api.main:app --reload --port 8000
```

```powershell
# Windows PowerShell
$env:API_MOCK="1"; python -m uvicorn src.api.main:app --reload --port 8000
```

浏览器打开 `http://127.0.0.1:8000`。mock 固定 `RUN20261121-01` / `RUN20261121-02`，案例对比页可直接使用。
